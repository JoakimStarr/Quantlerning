> **前置知识：** p7-l1/l3 组合与风控；p5-l6 VaR；p3-l7 交易成本。
> **学完能做什么：** 说清一条信号从生成到对账要经过哪六步、每步的失效模式是什么，理解模拟盘检验的是回测覆盖不到的后三步，能按上线清单推进模拟盘→小资金试运行。

## 为什么回测跑通了还要模拟盘

回测（第三章）回答「过去表现如何」，模拟盘（Paper Trading）回答「现在能不能跑起来」。这两个问题听起来只差一个时间，实际上是两类完全不同的失败模式：回测的失败是**策略层面**的（赚不到钱），模拟盘暴露的是**工程层面**的（策略赚得到的钱，系统拿不到）。原因很简单：回测里你拥有上帝视角——数据永远准时、订单永远全额成交、进程永远活着；实盘里这三件事没有任何一件有保证。

下面把一条信号的一生拆成六步，逐步看哪几步回测覆盖了、哪几步只有模拟盘能暴露。

## 一条信号的生命周期

以「双均线金叉 → 买入茅台」为例，从信号到入账共六步：

**① 信号生成。** 行情数据到达 → 计算均线 → 判断金叉。**失效模式**：行情延迟或缺失——你以为在用 14:59 的价格，其实是 14:50 的；数据断流时信号引擎拿旧数据继续算，产生「幽灵信号」。回测里不存在这个问题（历史数据一次性给全），模拟盘里它是第一天就会撞上的墙。

**② 风控检查。** 信号要过风控层：单标的仓位上限、组合回撤熔断、当日最大下单次数。**失效模式**：信号被拒后怎么办？放弃、缩量还是排队？回测从来没有「拒单」这个概念，模拟盘必须把拒绝路径也写成代码（p7-l3 的「风控代码化」在这一步落地）。

**③ 订单构造与发出。** 把目标仓位换算成具体订单：买多少股（A 股整手约束）、用什么价格（市价还是限价，p7-l5）、发往哪个柜台。**失效模式**：资金计算与持仓对不上（昨日成交未清算）、API 超时后订单实际发出但本地以为失败——重复下单的来源。

**④ 撮合成交。** 订单进入交易所排队。**失效模式**：部分成交（只成交 40%，剩下的怎么办）、涨跌停无法成交（回测里「纸上成交」的现场版）、滑点超出假设（p7-l5 的订单簿现实）。回测假设「次日开盘价全额成交」，模拟盘会给这条假设开第一张罚单。

**⑤ 回报与对账。** 券商回报成交明细 → 与本地持仓核对。**失效模式**：理论仓位 vs 实际持仓不一致（重复下单、部分成交漏记）。对账不一致是实盘最危险的信号之一——连「我现在有多少仓位」都不确定，后面所有计算都是空中楼阁。

**⑥ 记录与复盘。** 全程留痕：信号快照、订单、回报、当时的持仓与净值。**失效模式**：没记当时的行情快照，事后想复盘「当时为什么下单」却无据可查——这违反 p3-l1「可归因」的要求，也违反 p7-l3「风控可审计」的要求。

看清了吗？**回测只覆盖了第①步和第④步的理想化版本**；②③⑤⑥四步，加上①④的现实版本，全部是模拟盘的管辖范围。这就是「回测漂亮 ≠ 实盘能跑」的精确含义。

## 模拟盘 vs 回测 vs 实盘

| | 回测 | 模拟盘 | 实盘 |
|---|---|---|---|
| 数据 | 历史（已知结局） | 实时/滚动（未知结局） | 实时（真金白银） |
| 成交 | 假设（次日价/收盘价、全成） | 真实规则 + 滑点（虚拟资金） | 真实规则 + 真实冲击 |
| 风控 | 可以没有 | 必须代码化 | 必须代码化 + 熔断 |
| 失败代价 | 重跑 | 重启 | 亏损、不可逆 |
| 回答的问题 | 过去表现如何 | 现在能不能跑起来 | 现在正在赚钱还是亏钱 |

注意「失败代价」这一行：回测错了可以重跑，模拟盘错了可以重启，实盘错了就是亏损离场。**系统工程的投入应该与失败代价成正比**——这正是模拟盘存在的意义：用最低的成本把⑥步链路走扎实。

## 从模拟盘到券商 API：接口怎么接

- **账户与权限**：券商 API 需单独申请，权限分级（只读查询 → 模拟交易 → 实盘）——每一级都用够时间再申请下一级；
- **接口形态**：多数 A 股券商提供 Python SDK（QMT、miniQMT、掘金）或 REST/WebSocket 接口；
- **最小原则**：先用「只读 + 手动下单」跑通，再逐步自动化——第一次接 API 就全自动下单，等于把上面六步的所有失效模式一次性引爆破仓；
- **测试环境**：券商通常提供模拟环境，先在模拟环境验证接口与撮合规则，再接自己的模拟盘。

## 风控必须代码化：熔断的三个层级

实盘风控不能依赖人工纪律——亏损发生时人工恰恰最不可靠。按响应速度分三层写进代码（p7-l3 的工具在这一步变成守门员）：

1. **单笔层（毫秒级）**：单笔订单量上限、价格偏离保护（限价单价格带）、当日最大下单次数——挡住「信号抖动导致的高频乱单」；
2. **组合层（日内）**：组合日内回撤熔断——跌破阈值程序化减仓/清仓（p7-l3 的止损在此执行）；
3. **账户层（持续）**：总回撤熔断、最大持仓集中度、异常自动停止交易并告警——最后一道保险丝。

每一层都要有**告警**跟随：熔断触发不是静默的，必须立刻通知到你。

## 上线清单

- [ ] 模拟盘稳定运行 ≥ 1 个月，覆盖涨跌停、停牌、长假前后的成交窗口
- [ ] 六步链路各步的失效模式都有代码化处理（拒单、超时、部分成交、对账不一致）
- [ ] 券商 API 只读权限验证通过
- [ ] 三层风控全部代码化并通过压测（故意制造异常订单验证熔断会触发）
- [ ] 告警通道（短信/邮件）验证
- [ ] 小资金实盘试运行（如 1% 仓位），用真实滑点校准回测假设（p7-l5）

## 金融应用

- **模拟盘暴露「回测没发现的问题」**：数据延迟、API 异常、信号抖动、仓位计算溢出、对账差错——至少运行 1~3 个月、覆盖不同市况，再考虑实盘；
- **实盘准备的核心心态**：**假设会出错，而不是假设不会出错**。回测教我们策略，风控与运维教我们活着——先活下来，才能等到策略有效的那天；
- **共同局限**：模拟盘与实盘仍有差距（情绪、流动性冲击、部分成交的比例），它验证的是「跑得通」，不是「能赚钱」——最后一步永远是小资金试运行。

## 学完自检：三问

- **一条信号从生成到入账要经过哪六步？哪几步是回测覆盖不到的？**（答不出 → 回看生命周期一节）
- **「对账不一致」为什么是最危险的信号？**（答不出 → 回看第⑤步）
- **三层风控各在什么时间尺度上响应？你的策略配齐了吗？**（答不出 → 回看熔断三层级）

三问都能答上，你才算真正理解了「从回测到实盘」隔着什么——不是更好的策略，而是更扎实的工程。

## 练习题

**练习 1（选择题）：** 模拟盘与回测的本质区别。

:::quiz
Q: 模拟盘与回测最本质的区别是？
- 使用的数据完全不同
- 回测假设成交，模拟盘按真实撮合规则与滑点执行，检验落地能力
- 模拟盘可以快进
- 回测验证执行质量
A: 2
E: 回测用历史数据、假设次日价/收盘价成交；模拟盘在实时行情下按真实规则撮合，暴露信号、执行、风控的落地问题。
:::

**练习 2（选择题）：** 六步链路的归属。

:::quiz
Q: 「订单发出后 API 超时，本地以为失败但订单实际已成交」这类问题，属于信号生命周期六步中的哪一步、哪类环境才能暴露？
- 第①步信号生成，回测就能暴露
- 第③④步订单构造与撮合，只有模拟盘/实盘能暴露
- 第⑥步记录复盘，与成交无关
- 任何回测都能暴露
A: 2
E: API 超时与「订单状态不确定」是工程层失效：回测没有 API、没有超时，只有模拟盘/实盘才存在——这正是「回测覆盖不到后三步」的具体例子。
:::

**练习 3（应用题）：** 核算模拟盘滑点成本。

:::exercise
T: 模拟盘假设单边滑点 5bp（0.05%）。某策略每月调仓 2 次，每次调仓含 1 买 1 卖，组合规模 100 万元。请计算每月滑点成本占组合的比例与金额；若实盘实际单边滑点为 15bp，成本如何变化？这提示模拟盘应如何设置滑点假设。

追一问：若该策略年化收益目标为 $8\%$，按每月 $0.2\%$ 的滑点成本折算，年化滑点成本占收益目标的比例是多少？再把调仓频率提高到每月 4 次，比例又变为多少？请用这两个数字说明调仓频率与交易成本的权衡，以及为何高频策略对滑点极其敏感。

:::answer
- **主答**：每月成交 $=2$ 次 $\times2$ 笔 $\times100$ 万 $=400$ 万；滑点 $=400$ 万$\times5\text{bp}=2000$ 元、占 $0.2\%$。实盘 15bp：6000 元、$0.6\%$——**3 倍**。
- **追问**：年化滑点 $2.4\%$，占 8% 目标的 30%；4 次/月：$4.8\%$、占 60%——频率翻倍成本翻倍。启示：滑点假设按实盘可验证的保守值设定（试运行实测回填），策略先过「目标收益 vs 换手成本」的算术关——这正是模拟盘要暴露的第一类问题。
:::
:::

**练习 4（选择题）：** 实盘风控应落在哪一层。

:::quiz
Q: 实盘风控硬约束的正确实现方式是？
- 依赖交易员的纪律与经验
- 全部代码化，由程序强制执行的代码层
- 由券商柜台人工把关
- 每周人工复查
A: 2
E: 实盘不可逆，风控必须程序化：权限隔离、止损熔断、限频限单、异常兜底、审计日志，不能依赖人工纪律。
:::

**练习 5（应用题）：** 小资金试运行成本核算。

:::exercise
T: 上线清单要求小资金试运行（如 1% 仓位）。总资金 50 万元，试运行 1% 即 5,000 元；1 个月累计成交额 20 万元，实际滑点与冲击成本合计 400 元。请计算实际成本率，与模拟盘假设的单边 5bp 对比，并说明小资金试运行的意义。

追一问：若试运行结束后把仓位从 $1\%$ 放大到 $100\%$，请说明「把试运行成本率直接乘以资金」为何可能低估真实冲击成本（订单规模增大 → 相对订单簿深度不足 → 冲击成本非线性上升），并结合 p7-l5 的价格冲击概念分析。

:::answer
- **主答**：实际成本率 $=400/200000=20\text{bp}$，是假设 5bp 的 **4 倍**。意义：小资金试运行用最小代价实测真实摩擦（滑点、冲击、部分成交、API 异常）。
- **追问**：成本率不能线性放大：订单规模↑ → 占深度比例↑ → 冲击按 $\sqrt{Q/ADV}$ 超线性上升（p7-l5），且需拆单。100% 仓位的单笔冲击远高于 1% 仓位实测——应按「分档规模 × 冲击函数」重估并写进上线前测算，而非直接乘 100 倍。
:::
:::

**练习 6（选择题）：** 模拟盘验证结果的边界。

:::quiz
Q: 模拟盘稳定运行 1 个月、信号与风控都正常，此时最合理的判断是？
- 已充分验证，可直接上实盘
- 只证明了全链路「跑得通」，滑点/流动性/情绪等实盘差距仍需小资金试运行检验
- 回测结论自动成立
- 模拟盘收益可直接当作实盘预期
A: 2
E: 模拟盘回答「现在能不能跑起来」，不回答「实盘能不能赚」；模拟盘假设的滑点（如 5bp）常被实盘超越（练习 5 实测约 20bp），情绪与部分成交也无法模拟——上线清单把小资金试运行放在最后一步，正是为暴露这些差距。
:::
