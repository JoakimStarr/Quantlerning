## 读取与概览

**拿到数据的第一件事：读进来，看看里面有什么：** 所有分析都从这两步开始：

```python
import pandas as pd

df = pd.read_csv('daily.csv', parse_dates=['trade_date'])
df.info()      # 数据类型 / 缺失值
df.describe()  # 各列描述统计
df.head()      # 前 5 行
```

`parse_dates` 把日期列解析成真正的日期类型——不做这一步，后面的排序、重采样、合并都会出错。

**本项目的数据**：真实数据已同步到本地 PostgreSQL（quantlab 库），可通过**数据浏览器**直接查询 10 年 A 股日线；上机练习时也可导出 CSV 用 `read_csv` 读取。

## 清洗与检查

:::quiz
Q: `pd.read_csv('daily.csv', parse_dates=['trade_date'])` 中 `parse_dates` 的作用是?

- 删除缺失日期
- 把日期转成字符串
- 自动去重
A: 1
E: `parse_dates` 指定要解析为日期类型的列，日期类型才能正确排序、重采样与合并。
:::

**真实数据必有脏点**——停牌日缺失、异常价、类型错乱。清洗的顺序很重要：先排序、再清洗。

```python
df['trade_date'] = pd.to_datetime(df['trade_date'])
df = df.sort_values('trade_date').reset_index(drop=True)  # 先排序
df = df.dropna(subset=['close'])   # 去停牌日缺失
df = df[df['close'] > 0]           # 剔异常价（≤0）
df = df.drop_duplicates(subset=['trade_date'])
```

> 先排序再算收益，否则 `pct_change` 会错位。停牌日的缺失是**真实缺失**，不要插值掩盖——那是数据的真实状态。

**缺失值处理**。先分清缺失是「真实缺失」还是「数据缺口」：停牌日是真实缺失（保持 `NaN` 或前向填充）；瞬时成交量为 0 可用 `ffill` 填补。三类常用手法：

```python
df['close'].ffill()              # 前向填充：用最近有效值填补（停牌延续）
df['volume'].fillna(0)           # 无成交填 0（更接近真实交易状态）
df['turn'].interpolate()         # 线性插值：仅用于「测量缺口」，勿用于停牌
```

**重复与类型**。`drop_duplicates` 处理重复行；`astype` 修正类型错乱（把「12,345」字符串转数值要先去逗号）：

```python
df = df.drop_duplicates(subset=['trade_date', 'code'])
df['amount'] = df['amount'].astype(str).str.replace(',', '').astype(float)
```

:::quiz
Q: 对停牌导致的收盘价缺失，正确的处理是?
- 用插值掩盖，让曲线连续
- 视为真实缺失，保持 NaN 或前向填充，不要伪造数据
- 直接删除整只股票
- 用未来数据回填
A: 2
E: 停牌缺失是数据的真实状态，插值会伪造数据。可用 `ffill`(前向填充)或保留 NaN。
:::

## 收益与滚动指标

**行情变「可分析数据」的起点是收益率与滚动指标**：

```python
df['ret'] = df['close'].pct_change()                        # 日收益
df['log_ret'] = np.log(df['close']).diff()                  # 对数收益
df['ma20'] = df['close'].rolling(20).mean()                 # 20 日均线
df['vol20'] = df['ret'].rolling(20).std() * (252 ** 0.5)   # 20 日年化波动
df['hh20'] = df['high'].rolling(20).max()                   # 唐奇安上轨
df['ll20'] = df['low'].rolling(20).min()                    # 唐奇安下轨
```

**两个容易踩的坑**：
- **复权**：分红后价格才可比，用**复权价**算收益（见 Phase 1 p1-l1）——不复权的「价差」混入了分红扰动；
- **年化**：年化波动乘 $\sqrt{252}$，252 是 A 股年化交易日数。

:::quiz
Q: A 股日收益年化时，波动率应乘以?
- 12
- $\sqrt{252}$
- 252
- 1
A: 2
E: 年化波动乘 $\sqrt{252}$，其中 252 是 A 股年化交易日数(标准差随 $\sqrt{n}$ 缩放)。
:::

## 特征工程

**特征工程是把原始行情「加工成机器学习/因子模型能吃的特征」**。三类核心方法：去极值、标准化、滞后与窗口特征。

**去极值（winsorize）**。极端值（一字跌停、暴涨暴跌）会把均值拉偏、把模型带歪。用**中位数绝对偏差（MAD）**做稳健的裁剪，比用均值±标准差更抗噪：

```python
def winsorize_mad(x, n=3)：
    med = x.median()
    mad = (x - med).abs().median()
    lo, hi = med - n * 1.4826 * mad, med + n * 1.4826 * mad
    return x.clip(lo, hi)  # 超出阈值拉到边界

df['ret'] = winsorize_mad(df['ret'])
```

其中 `1.4826` 把 MAD 归一到标准差尺度（$MAD \approx 0.6745\sigma$），$n=3$ 约为 ±3σ。

**标准化（z-score）**。不同特征量纲不同（收益是百分之几、成交额是亿元、PE 是几十倍），直接喂给模型会把量纲大的特征权重带偏。标准化让每个特征均值为 0、标准差为 1：

```python
df['z'] = (df['ret'] - df['ret'].mean()) / df['ret'].std()
```

或直接用 `sklearn.preprocessing.StandardScaler`。**注意**：在回测中标准化要在每个截面内做、且只用当时已知的历史统计量——用未来全局均值去标准化就是前视偏差（见 Phase 1 p1-l10）。

:::viz feature_pipeline caption=特征工程流水线（真实茅台 2024 日收益）：点「原始收益 → MAD 去极值 → z-score 标准化」看每一步的效果。原始收益有明显的厚尾（极端值把分布拉开）；去极值把 ±3σ 外的点裁到边界，直方图不再被离群点拉宽；标准化把均值归 0、标准差归 1，橙色虚线是正态参考曲线——左尾明显更厚，说明真实收益不服从正态。
:::

**滞后与窗口特征**。时间序列模型不能「用未来预测自己」，特征必须只含历史信息：

```python
df['ret_prev'] = df['ret'].shift(1)                  # 上一日收益（滞后 1）
df['mom20'] = df['close'] / df['close'].shift(20) - 1  # 20 日动量
df['z_vol20'] = (df['vol20'] - df['vol20'].mean()) / df['vol20'].std()
```

`shift` 把「当天收盘」变成「用昨天收盘已知」；窗口特征（滚动均值/波动）天然只含历史。**任何特征若在时刻 $t$ 用到了 $t$ 之后的信息，回测就会虚高**——这是特征工程里最容易犯、也最致命的错误。

:::quiz
Q: 回测中做特征标准化时，正确的做法是?
- 用全样本均值/标准差
- 每个截面内、只用当时已知的历史统计量，避免前视偏差
- 用未来数据校准
- 跳过标准化
A: 2
E: 用未来全局均值/标准差去标准化就是前视偏差——回测会虚高。必须在每个截面内只用当时已知的历史统计量。
:::

## 重采样与截面

**降频与摊开：** 把日频数据「降频」成月频，或把多股票「摊开」成横截面（每列一只股票）：

```python
df = df.set_index('trade_date')
monthly = df['close'].resample('M').last()   # 月频（每月最后收盘）
rolling = df['ret'].resample('W').sum()      # 周频收益
pivot = df.pivot_table(index='trade_date', columns='code', values='close')
cross_ret = pivot.pct_change()               # 每列一只股票的日收益
```

重采样是降频、pivot 是转截面——一个是时间上的聚合，一个是结构上的展开，Phase 2 的横截面因子分析处处依赖 `cross_ret` 这种宽表。

:::quiz
Q: `df.pivot_table(index='trade_date', columns='code', values='close')` 得到的是?
- 单只股票的日频序列
- 宽表:每行一个交易日、每列一只股票的收盘价(横截面)
- 月频数据
- 合并后的财务表
A: 2
E: pivot 把数据「摊开」成宽表——行是日期、列是股票，这就是横截面分析依赖的 `cross_ret` 结构。
:::

## 多表合并与对齐

**行情、财务、指标分属不同表，按「代码 + 日期」对齐拼合**：

```python
# 行情 + 行业
merged = pd.merge(daily, stock_basic[['code', 'name']], on='code', how='left')

# 行情 + 财务（注意财报滞后，用 PIT 对齐，避免前视偏差）
merged = pd.merge(
    daily, financial_indicator,
    on=['code', 'trade_date'], how='left'
)
```

**前视偏差陷阱**：财务数据的 `trade_date` 是**报告期归属**，真正的「可用日期」可能滞后数月。做回测对齐时要用 PIT（Point-in-Time）口径——只使用当时已知的信息，否则会「偷看未来」，回测虚高（Phase 1 p1-l10 详讲）。

:::quiz
Q: 用财务数据与行情合并做回测时，为什么要用 PIT(Point-in-Time)口径?
- 提高合并速度
- 财务数据的报告期归属滞后于实际可用日期，用 PIT 只用当时已知信息，避免前视偏差
- 让数据更完整
- 因为财务数据不需要对齐
A: 2
E: 财报 `trade_date` 是报告期归属，可用日期可能滞后数月。PIT 口径只使用当时已知信息，否则「偷看未来」会让回测虚高。
:::

**练习 1（选择题）：** 先排序再算收益。

:::quiz
Q: 计算 `df['ret'] = df['close'].pct_change()` 之前，必须先做哪一步？
- 按 `trade_date` 排序，否则相邻行不是时间上相邻的交易日，收益会错位
- 删除所有负数
- 填充所有缺失值
- 把日期转成字符串
A: 1
E: `pct_change` 用相邻行之差，若数据未按日期排序，算出的「收益」是乱序行之间的变化——先排序再算收益是铁的纪律。

**练习 2（选择题）：** MAD 去极值的常数。

:::quiz
Q: `winsorize_mad` 中阈值取 `med ± n * 1.4826 * mad`，其中 `1.4826` 的作用是？
- 把 MAD 归一到标准差尺度（$\text{MAD}\approx0.6745\sigma$，故 $1/0.6745\approx1.4826$）
- 把数据放大 1.4826 倍
- 表示 1.4826 个交易日
- 无意义，可随意替换
A: 1
E: 正态下 MAD 约为标准差的 0.6745 倍，取倒数 $1.4826$ 把 MAD 换算成 $\sigma$ 尺度，$n=3$ 即约 ±3σ 裁剪，比均值±标准差更抗离群点。
:::

**练习 5（选择题）：** 缺失处理中的前视偏差。

:::quiz
Q: 回测中处理时间序列的缺失值时，下列哪种方法会引入前视偏差（在 $t$ 时刻用到未来信息）？
- `ffill()`（前向填充）
- `fillna(0)`
- `interpolate()`（线性插值）
- `dropna()`
A: 3
E: 线性插值要用缺失点两侧（含未来）的值加权拟合，$t$ 时刻就「知道了」未来；`ffill` 只用历史、`fillna(0)` 是常数、`dropna` 直接剔除，均不含未来。回测中「宁可删行，不可偷看未来」。
:::
