## 定义

模拟盘（Paper Trading）让策略在真实行情上以虚拟资金运行，验证「代码里的策略」能否变成「可执行的策略」。回测（第二章）回答「过去表现如何」，模拟盘回答「现在能不能跑起来」。

## 模拟盘 vs 回测

| | 回测 | 模拟盘 |
|---|---|---|
| 数据 | 历史（已知结局） | 实时/滚动（未知结局） |
| 成交 | 假设（次日价/收盘价） | 实盘撮合规则 + 滑点 |
| 目的 | 验证策略有效性 | 验证执行与运维 |
| 时间 | 可快进 | 实时推进 |

回测的假设（p2-l5 前视偏差、p2-l7 交易成本）在模拟盘中被真实检验：信号能否及时生成、订单能否按预期成交、风控规则能否触发。

## 模拟盘要素

1. **信号引擎**：读取实时行情 → 生成目标仓位；
2. **执行模拟**：按真实规则撮合（涨跌停、停牌、滑点、手续费）；
3. **风控层**：止损、仓位上限、单笔限额（p6-l3）；
4. **监控面板**：实时净值、回撤、持仓、成交记录。

## 实盘准备：从跑得通到跑得稳

实盘准备（Go-Live Preparation）是策略上线的系统工程。核心变化：回测/模拟盘的「可重来」变成实盘的「不可逆」——每一笔成交都是真金白银，每一个 bug 都有真实成本。

## 券商 API 接入

- **账户与权限**：券商 API 需要单独申请，权限分级（只读查询 → 模拟交易 → 实盘）；
- **接口形态**：大多数 A 股券商提供 Python SDK（如 QMT、掘金、miniQMT）或 REST/WebSocket 接口；
- **最小原则**：先用「只读 + 手动下单」跑通，再逐步自动化；
- **测试环境**：券商通常提供模拟环境，先在模拟环境验证接口与撮合规则。

## 实盘风控硬约束

实盘风控必须落在**代码层**，不能依赖人工纪律：

1. **权限隔离**：策略只能操作指定账户、指定标的池、指定仓位上限；
2. **止损熔断**：总回撤超阈值 → 程序化清仓（p6-l3）；
3. **限频限单**：防止信号抖动导致的高频乱单；
4. **异常兜底**：网络断线 → 挂单超时处理、持仓不匹配告警；
5. **审计日志**：所有决策与成交留痕，可追溯。

## 监控与告警

- **净值/回撤**：实时监控，跌破阈值立即告警；
- **成交偏差**：理论仓位 vs 实际持仓不一致告警；
- **行情源**：数据中断、延迟异常告警；
- **运维**：进程存活、系统资源、API 配额监控。

## 上线清单

- [ ] 模拟盘稳定运行 ≥ 1 个月，覆盖涨跌停、停牌、长假
- [ ] 券商 API 只读权限验证通过
- [ ] 风控规则全部代码化并通过压测
- [ ] 告警通道（短信/邮件）验证
- [ ] 小资金实盘试运行（如 1% 仓位）

## 金融应用

- **模拟盘**暴露「回测没发现的问题」：数据延迟、API 异常、信号抖动、仓位计算溢出；至少运行 1~3 个月模拟盘，覆盖不同市况，再考虑实盘；
- **实盘准备**的核心心态：**假设会出错，而不是假设不会出错**。回测教我们策略，风控与运维教我们活着——先活下来，才能等到策略有效的那天；
- **共同局限**：模拟盘与实盘仍有差距（情绪、流动性冲击、部分成交），但它是成本最低的演练。

## 与本章的关系

模拟盘把前六章的能力集成：数据（第一章）、策略（第二章）、因子（第三章）、ML 预测（第五章）、组合与风控（第六章）。它是「完整 pipeline」的预演，下一节进入实盘准备。

## 练习题

**练习 1（选择题）：** 模拟盘与回测的本质区别。

:::quiz
Q: 模拟盘与回测最本质的区别是？
- 使用的数据完全不同
- 回测假设成交，模拟盘按真实撮合规则与滑点执行，检验落地能力
- 模拟盘可以快进
- 回测验证执行质量
A: 2
E: 回测用历史数据、假设次日价/收盘价成交；模拟盘在实时行情下按真实规则撮合，暴露信号、执行、风控的落地问题。
:::

**练习 2（应用题）：** 核算模拟盘滑点成本。

:::exercise
T: 模拟盘假设单边滑点 5bp（0.05%）。某策略每月调仓 2 次，每次调仓含 1 买 1 卖，组合规模 100 万元。请计算每月滑点成本占组合的比例与金额；若实盘实际单边滑点为 15bp，成本如何变化？这提示模拟盘应如何设置滑点假设。

追一问：若该策略年化收益目标为 $8\%$，按每月 $0.2\%$ 的滑点成本折算，年化滑点成本占收益目标的比例是多少？再把调仓频率提高到每月 4 次，比例又变为多少？请用这两个数字说明调仓频率与交易成本的权衡，以及为何高频策略对滑点极其敏感。

:::

**练习 3（选择题）：** 实盘风控应落在哪一层。

:::quiz
Q: 实盘风控硬约束的正确实现方式是？
- 依赖交易员的纪律与经验
- 全部代码化，由程序强制执行的代码层
- 由券商柜台人工把关
- 每周人工复查
A: 2
E: 实盘不可逆，风控必须程序化：权限隔离、止损熔断、限频限单、异常兜底、审计日志，不能依赖人工纪律。
:::

**练习 4（应用题）：** 小资金试运行成本核算。

:::exercise
T: 上线清单要求小资金试运行（如 1% 仓位）。总资金 50 万元，试运行 1% 即 5,000 元；1 个月累计成交额 20 万元，实际滑点与冲击成本合计 400 元。请计算实际成本率，与模拟盘假设的单边 5bp 对比，并说明小资金试运行的意义。

追一问：若试运行结束后把仓位从 $1\%$ 放大到 $100\%$，请说明「把试运行成本率直接乘以资金」为何可能低估真实冲击成本（订单规模增大 → 相对订单簿深度不足 → 冲击成本非线性上升），并结合 p6-l5 的价格冲击概念分析。

:::

**练习 5（选择题）：** 模拟盘验证结果的边界。

:::quiz
Q: 模拟盘稳定运行 1 个月、信号与风控都正常，此时最合理的判断是？
- 已充分验证，可直接上实盘
- 只证明了全链路「跑得通」，滑点/流动性/情绪等实盘差距仍需小资金试运行检验
- 回测结论自动成立
- 模拟盘收益可直接当作实盘预期
A: 2
E: 模拟盘回答「现在能不能跑起来」，不回答「实盘能不能赚」；模拟盘假设的滑点（如 5bp）常被实盘超越（练习 4 实测约 10bp），情绪与部分成交也无法模拟——上线清单把小资金试运行放在最后一步，正是为暴露这些差距。
:::
